# Evaluation report

Generated by `mindbridge eval`. The coverage cutoff is the shipped default, not re-fitted here.

How to read the splits: `dev` was used while building the system, and the keyword metadata in `data/kb` and the crisis rules were written with the dev and test queries in view, so both are close to saturated and say little. `holdout` was written afterwards and is the number to trust for retrieval and scope. For crisis detection, the holdout exposed gaps that were then fixed in the rules, so its safety row is no longer a clean held-out measurement either.

## Caveats

- The sets are small and written by the author of the system, so they flatter it. Treat the numbers as a regression guard, not a benchmark.
- Crisis rules were fitted to the cases the author could think of. Real messages are messier; a rule-based detector will miss phrasings, which is why helplines are always reachable from the UI and why an optional LLM second opinion exists for borderline text.
- Numbers here use the offline LSA embedder. The sentence-transformers path was not run for this report.
- Generation quality (groundedness, tone) is not covered here because it needs a live model; see docs/design-decisions.md for how it is checked manually.
